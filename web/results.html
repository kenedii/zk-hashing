Results

What has been built and measured. Memory figures are measured unless marked as estimates; estimates follow the cost model.

Summary of findings

  • Complete circuits. RFC 9106 Argon2id v1.3 and bcrypt 2b execute in full as Miden programs and agree with the RustCrypto reference implementations, including on a 64-case Argon2id parameter matrix.
  • Proof generation is memory-bound. Peak prover memory is linear in the padded trace length, at about 8.5 KiB per row. The smallest Argon2id configuration (225 rows) requires an estimated 272 GiB; bcrypt at cost 4 (229 rows) about 4.3 TiB.
  • Verification is inexpensive. A 172 KB MiMC-7 proof verifies in 10–100 ms with the WebAssembly build of the verifier.
  • Browser proving is bounded by the 32-bit address space. MiMC-7 proving peaks at 4.25 GiB natively; the wasm32 build in Chromium reaches the 4 GiB ceiling and makes no further progress. A Memory64 build is the direct remedy.
  • Hash-based assumptions only. Soundness rests on collision-resistant hashing rather than on discrete-logarithm hardness, so the construction is not exposed to Shor's algorithm.

The memory wall

Password hashes are expensive by design, and a general-purpose prover stores every step of the computation.

The prover materializes the full execution trace and its low-degree extension before committing, and the trace length is padded to the next power of two. Lowering the proof security level does not help, because the trace itself is the dominant cost. Memory therefore scales with the hash's work factor: the property that makes Argon2id and bcrypt resist guessing is exactly what makes them expensive to prove.
