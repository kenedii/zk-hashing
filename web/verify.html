    What each action tests

    Verify the login
    Checks 𝖵𝖾𝗋𝗂𝖿𝗒(hP,(C,s,θ,n),π)=1 with every public value taken from the server's records.
    Flip one bit
    Alters one random bit of the proof body. Merkle authentication paths and FRI consistency checks reject the result.
    Replay against a new challenge
    Presents the same proof for a fresh n′≠n. Because n is absorbed into the Fiat–Shamir transcript, every derived challenge changes and verification fails.
    Check against another password
    Computes the commitment C′ of the entered password and verifies the proof against it. The proof verifies only for the registered C.

    EXPERIMENTAL / RESEARCH PROTOTYPE. Unaudited; must not protect real accounts.
